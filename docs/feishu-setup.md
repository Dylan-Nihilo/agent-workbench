# Workbench 飞书连接指南

Agent Workbench（界面简称 Workbench）使用官方 `@larksuiteoapi/node-sdk` 的应用注册流程和 WebSocket 长连接。此 demo 创建专用机器人，不读取或修改全局 `lark-cli` 配置，不绑定已有业务机器人。

当前已实机验证扫码创建、长连接、操作者配对，以及完成 macOS 授权后恢复原有加密配置。飞书任务进入 Agent、读取网页并回传结果的最终联调仍在确认。以下是实际界面和代码支持的操作流程。

## 1. 创建专用机器人

1. 在 `agent-workbench` 仓库运行 `npm run dev`，或打开已打包的 `Agent Workbench.app`，进入「设置与连接 → 飞书」。
2. 点击「创建专用机器人」，等待二维码出现。获取二维码失败或过期时，按界面提示重试。
3. 用飞书扫码，确认**创建新应用**。应用名称默认预填 `Workbench Demo`，以确认页最终名称为准。
4. 检查确认页权限。Workbench 请求下面两项应用身份权限和一个事件，不请求用户 OAuth 文档访问权限。

| 项目 | 标识 | 用途 |
|---|---|---|
| 读取机器人单聊消息 | `im:message.p2p_msg:readonly` | 接收发给机器人的单聊文本 |
| 以机器人身份发送消息 | `im:message:send_as_bot` | 在已配对原会话回复结果 |
| 接收消息事件 | `im.message.receive_v1` | 通过长连接获取消息 |

SDK 调用使用 `createOnly: true` 和 `addons.preset: false`。前者限制注册页只创建新应用；后者请求最小机器人模板。SDK 的附加配置能力受平台支持情况影响，实际权限以扫码确认页、开发者后台和租户审批结果为准，不能仅凭代码参数判断已生效。[官方 SDK 注册说明](https://github.com/larksuite/node-sdk#app-registration)

凭据由 SDK 返回主进程，随后立即加密保存并启动长连接。扫码流程不会把 App Secret 放进聊天、二维码说明或回传 renderer 的连接状态。二维码和注册链接只用于本次设置，避免转发给其他人；不再继续时，可点击「取消创建」结束本地等待。

## 2. 配对当前操作者

“连接已建立”表示 WebSocket 已连通；**只有完成配对后才接受任务**。

1. 在飞书找到刚刚创建的机器人，打开单聊。
2. 复制 Workbench 显示的完整配对消息，格式为 `绑定 WB-XXXX-XXXX-XXXX-XXXX`，发送到该机器人。这里的示例不是有效配对码。
3. 等待机器人确认及 Workbench 显示已配对。

配对码使用 64 位随机值，仅显示在本机，约 10 分钟有效；多次错误尝试会更换代码。当前实现还接受 `/pair CODE` 或 `配对 CODE`。Workbench 校验消息属于当前应用，且消息所在租户与发送人租户一致，再用正确配对码绑定该消息的应用内用户身份、原始单聊和租户。只处理普通文本和富文本中的可见文字；群聊、跨租户消息、其他发送人、图片和附件不会交给 Agent。

注册结果中的 `user_info.open_id` 没有明确的应用作用域契约，因此不拿它与新机器人的消息用户 ID 直接比较。配对建立的是这次真实机器人消息所携带的身份；不要将配对码交给其他人。

不要把配对码发到群聊或交给别人。重连保留已保存的绑定；断开连接不会撤销应用或删除飞书后台权限。

## 3. 发起与停止任务

点击 Workbench 右上角「展开浏览器」，在同一窗口的右侧面板打开本地示例页，再试一条任务。该面板可调整宽度，页面由 neo 以 Retina DPR 2 渲染；飞书任务操作的也是这个页面，不会另外弹出浏览器窗口：

```text
查看当前页面，告诉我有哪些可以操作的元素。先不要提交表单。
```

结果会保存在 Workbench，并回复到发送任务的同一单聊。保持工作目录不变时，同一远程会话可继续已有对话。Workbench 同一时刻只运行一个 Agent 任务；需要命令或文件权限确认时，回到 Mac 的 Workbench 界面处理。

连接并配对后，机器人也会通知桌面发起任务的进展节点：

- **本轮结束**：发送回复摘要。Agent 用普通文本提出的问题也会随回复送达；这不等于所有业务目标已完成。
- **执行失败或停止**：通知当前任务状态；结果仍可在 Workbench 查看。
- **等待回答或审批**：告诉你待处理事项，并提示回 Mac 回答或审核。选择题不会替你预选；被 CLI 标记为敏感的问题及该轮结果内容不发送到飞书，完整命令与权限详情只在桌面显示。

当前版本只通知，不能在飞书远程批准命令或回答阻塞问题。通知只发送给已配对操作者的原始私聊，不广播到群聊。重复事件去重，已解决的排队提醒会跳过；投递失败不会重新执行任务，断线期间不补发过期提醒。

停止指令为任意一个：

```text
/cancel
停止
取消
```

停止请求会越过普通任务队列，但已完成的网页操作不会因此撤销。请查看实际页面和本机任务记录确认停止位置。

## 4. 手动配置备用路径

如果扫码注册不适用于当前租户，可在 [飞书开发者后台](https://open.feishu.cn/app) **新建一个 demo 专用企业自建应用**，再使用 Workbench 中的手动凭据入口。这里的“已有应用凭据”指刚为这个 demo 创建的应用，不应使用现有生产机器人。

1. 启用机器人能力。
2. 在权限管理申请上表两项应用身份权限。
3. 在「凭证与基础信息」获取 App ID 与 App Secret，输入 Workbench 并连接。
4. 在「事件与回调」选择使用长连接接收事件，添加 `im.message.receive_v1`。如后台要求先检测到连接，保持 Workbench 的连接过程并按提示保存。
5. 完成租户要求的应用发布、审批和可用范围配置，确保当前操作者可以打开机器人。
6. 返回 Workbench 重连，按第 2 节完成配对。

官方参考：[Node SDK 长连接与事件接收](https://github.com/larksuite/node-sdk) · [飞书开放平台](https://open.feishu.cn/)

## 常见情况

| 现象 | 检查方式 |
|---|---|
| 一直获取不到二维码 | 检查 Mac 能否访问飞书账号服务；Workbench 获取二维码超过 30 秒会退出并提示重试 |
| 扫码成功，仍连接失败 | 检查机器人能力、发布状态、租户审批、长连接事件订阅与网络；凭据成功保存后可点击连接已保存的机器人 |
| 更新后显示恢复中或恢复超时 | 由用户本人处理 macOS 钥匙串授权，再点击“重试恢复连接”；15 秒超时后旧配置仍保留，不需要重新扫码 |
| 已连接但发消息没有执行 | 先完成配对；确认发给正确机器人、使用原始单聊，且消息包含普通文本或富文本中的可见文字 |
| 只收到配对成功提示 | 再发送一条普通任务，例如“告诉我当前网页的标题，只读取，不要操作页面”；配对回复不代表 Agent 已执行任务 |
| 有回复但任务等待中 | 查看 Mac 上是否有 Agent 权限确认；需要本机已登录的 Codex |
| 结果未发回飞书 | 检查发送权限与网络，本机聊天仍保留结果；不要直接重复有副作用的操作 |
| 上次任务中断 | 程序重启不会自动重跑已开始的任务，先检查实际执行结果，再决定是否重发 |
| Mac 睡眠或 Workbench 退出 | 本地执行与连接停止；恢复运行后重新连接，不承诺补收所有离线消息 |

消息先加密写入本地 inbox，再交给后台任务；`message_id` 用于持久去重。任务错误和发送失败会反馈到桌面状态，失败不会自动重试。该机制减少重复操作，但不等于远端操作的事务回滚。

连接数据位于 Electron `userData/feishu/`，可通过 `WORKBENCH_USER_DATA_DIR` 更改数据目录。`credentials.enc` 包含加密的应用凭据和绑定，`inbox/` 保存加密的消息与处理状态。不要将这些数据、二维码链接或 App Secret 提交到仓库；不要复制凭据到另一台 Mac 并同时运行同一机器人。
